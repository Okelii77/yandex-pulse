# Yandex Pulse

**Независимая панель мониторинга сервисов Яндекса** — яркая, адаптивная, с тёмной и светлой темами, мобильной навигацией и историей проверок.

> **Важно:** Yandex Pulse не связан с ООО «Яндекс» и не является официальной статус-страницей. Проверки выполняются из GitHub Actions и показывают доступность *конкретных точек входа* для *конкретного клиента*. «Отвечает» не означает исправность всех функций сервиса.

## Интерфейс

- 10 разделов: Музыка, Облако, Почта, Диск, ID, Вики, Карты, Поиск, AI и другие сервисы.
- Проверки веб-интерфейсов, публичных API и TLS-подключений.
- Включаемые отдельно авторизованные проверки Music REST, Ynison, History и Queues.
- Поиск, фильтрация, подробная карточка проверки, графики отклика за 24 ч / 7 д / 30 д.
- Автообновление опубликованных данных раз в минуту, темы, адаптация под iPhone.
- SVG favicon, web app manifest, добавление на домашний экран.
- Всё на статическом хостинге: без VPS и отдельного платного сервера.

## Запуск

1. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. **Settings → Actions → General → Workflow permissions**: выберите **Read and write permissions**, если workflow не может сохранять \`site/status.json\` и \`site/history.json\`.
3. **Actions → Yandex Pulse · Check & Publish → Run workflow**. Дождитесь успешного выполнения **Synthetic checks** и **Publish Pages**.
4. Сайт: **https://okelii77.github.io/yandex-pulse/**

Проверки запускаются каждые ~30 минут и при коммитах в \`main\`. GitHub может задерживать расписание. При отсутствии свежих данных UI покажет «Данные устарели». Кнопка ↻ обновляет **отображение последнего опубликованного отчёта**, а не инициирует новую серверную проверку.

## Какие проверки возможны?

| Проверка | Что означает «Отвечает» | Чего НЕ означает |
| --- | --- | --- |
| HTTP | Синтетический запрос получил 2xx или редирект 3xx | Что логин, личный кабинет и все API работают |
| TCP/TLS | Установлено защищённое соединение с портом | Что можно войти и отправить письмо |
| Object Storage gateway | Шлюз ответил; анонимный запрет 403 показывается как «Ограничено» | Что можно читать или писать в бакет |
| Music REST с токеном | Авторизованный запрос к Яндекс Музыке прошёл | Что плеер и Ynison работают |
| Music History | API вернул историю / пустой результат | Что история обновляется в реальном времени |
| Music Queues | API ответил с очередями / пустым результатом | Что доступен текущий трек |
| Ynison | Клиент смог получить состояние воспроизведения | Что сервис работает для всех пользователей |

Коды \`401\`, \`403\`, \`404\`, \`429\` помечаются как **«Ограничено»**, поскольку могут означать политику доступа, блокировку запросов из GitHub, отсутствие авторизации или неподходящий URL. Ошибка HTTP 5xx — не доказательство массового сбоя: это лишь неудачная синтетическая проверка.

### Авторизованные проверки Яндекс Музыки (необязательно)

**По умолчанию отключены.** Все публичные HTTP/TLS-проверки работают без ключей. Для тестирования Music REST / History / Queues / Ynison требуется добавить Actions Secret \`YANDEX_MUSIC_TOKEN\` в **Settings → Secrets and variables → Actions**.

Рекомендации:

- **Не используйте основной аккаунт**, если можно обойтись отдельным тестовым. Токен предоставляет доступ к данным аккаунта.
- Никогда не коммитьте OAuth-токен, cookies, имена пользователей или логи с приватными данными.
- В опубликованные JSON попадают только статус, время ответа, числовые коды ошибок и *безопасные* диагностические поля. Названия песен, идентификаторы устройств, ID аккаунта и токен не сохраняются.
- Ошибка Ynison \`go_away_seconds\` сохраняется как время разрешённого следующего запроса. Пока пауза не истекла, сервер не опрашивается, а монитор показывает статус **«Пауза»**. GitHub Actions не гарантирует точное время запуска.
- Проверки выполняются из инфраструктуры GitHub: возможны сетевые ограничения, не характерные для пользовательского устройства.

Если нет отдельного тестового токена, **лучше оставить Ynison «Не настроено»**, а прямые проверки с личным токеном выполнять локально.

## Добавление нового сервиса

Отредактируйте [monitor/services.json](monitor/services.json). Например:

\`\`\`json
{
  "id": "new-web",
  "category": "other",
  "name": "Новый веб-сервис",
  "detail": "Доступность публичной главной страницы",
  "kind": "http",
  "url": "https://example.org/"
}
\`\`\`

\`category\` должен совпадать с существующей категорией, \`id\` должен быть уникальным.

Поддерживаемые виды: \`http\`, \`http_gateway\`, \`tcp_tls\`, \`requires_key\`, \`music_rest\`, \`music_history\`, \`music_queues\`, \`music_ynison\`. Последний набор требует OAuth-токена и дополнительной библиотеки.

Для проверки действия, меняющего состояние аккаунта (отправка письма, загрузка файла и т. д.), нужен **отдельный безопасный тестовый сценарий**; одной проверки главной страницы недостаточно.

## Структура

\`\`\`text
.github/workflows/pulse.yml    # Запуск и публикация GitHub Actions
monitor/services.json          # Категории, эндпоинты и типы проверок
monitor/check.py               # Синтетические проверки, история и cooldown
monitor/requirements.txt       # Python зависимости
site/index.html                # Доступный адаптивный интерфейс
site/styles.css                # Тёмная и светлая дизайн-системы
site/app.js                    # Фильтры, графики, поиск, вкладки
site/icon.svg                  # Логотип для PWA
site/favicon.svg               # Favicon
site/manifest.webmanifest      # Установка на главный экран
site/status.json               # Автоматически публикуется Actions
site/history.json              # Хронология последних 30 дней
\`\`\`

**Почему без React?** Это статическая статус-панель без тяжёлых зависимостей. Обычный HTML/CSS/JS проще обслуживать, быстрее отдавать мобильным браузерам и легче развернуть на GitHub Pages. Данные отделены от отображения, поэтому при необходимости интерфейс можно перенести на React.

## Архитектура и безопасность

\`\`\`text
GitHub Actions (каждые 30 минут)
       ↓
Python: публичные HTTP/TLS + необязательные авторизованные проверки
       ↓
site/status.json + site/history.json
       ↓
GitHub Pages: статический HTML/CSS/JS
       ↓
Браузер / телефон — только чтение открытых статусов
\`\`\`

Сайт **не принимает OAuth-токены** и **не выполняет запросы к личным данным** из браузера. Ни GitHub Pages, ни JavaScript не имеют доступа к Actions Secrets.
