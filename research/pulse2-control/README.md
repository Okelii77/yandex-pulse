# Isolated TypeScript control plane
Local workerd/D1 test, no deployment configuration or account credentials. SQL lease and publication fencing, atomic D1 batch, lazy history by source revision and 30-minute epoch, lock and compare-and-set, ETag, series delta, cleanup preserves the original 90-day raw retention policy and 30-day display. Local scheduler tests mocked dispatch, never invokes GitHub. Real dispatch disabled without explicit RC flag and token; the target workflow does not exist on main. OIDC restricts repo ID, branch, workflow and separate RC audience. Production manual trigger and Ynison endpoints are intentionally absent in this isolated service, so it is not a drop-in replacement. Before staged use, integrate current Turnstile and Ynison routes with the existing authoritative gate, test claim/dispatch on approved separate resources, and audit quotas. A local-only fixed token is for fixture CI; never configure it in a deployed worker. History revision is a string, requires RC frontend client. Tests do not claim cloud billing or latency.
Follow-up: reserved -> running transition is atomic, one runner may consume a dispatch claim, then publish under the same token. Start expiry is renewed; wrong/expired/replayed claims cannot start probes. `run-approved.py` and `dispatch-workflow.DRAFT.yml` are staged deployment drafts, not active workflow definitions. GitHub scheduled runs execute on the default branch, so fallback cron is deliberately not registered for the RC branch; after migration a fallback on main must share the same claim endpoint and OIDC ref policy. No real external dispatch until approved.
