# RC2 budget and OIDC constraints
App reservation limits per UTC day: 4,000 admitted API operations, at most 52 acquisition attempts (default deployment 1 for one-shot smoke), 1.5M estimated D1 rows read and 12k estimated writes. Each API reserves 32 reads and 2 writes; each ingest reserves extra 128 reads/100 writes; lazy history reserves 128 + 68 * min(revision,1440). These are conservative workload reservations, not actual account-wide billable metering; denied requests still reach Worker and D1 budget check. No absolute incoming-request ceiling is possible inside Worker; do not expose prolonged staging schedule until real shared usage is confirmed. Lease max 2 per slot, one active run, owner tied to run ID/attempt. OIDC per request fresh signed JWT; reject wrong issuer, audience, repo, ID, branch, environment, subject, event and workflow; consume jti once, enforce expiry. No production secrets. Dispatch and ingest flags separate. Cron remains off. Cleanup is explicit bounded maintenance; prior per-tick cleanup suspended pending budget review. Manual trigger needs separate scoped dispatch credential and real Turnstile; no token created. Real APIs prohibited. Before observation enable a capped daily schedule only after approval and verified shared metrics; if budget denied, no further dispatch. Revoke dispatch token and disable schedules for emergency shutdown. No billing upgrades.
