# Pulse 2.0 local system candidate

The Go and Rust applications exercise all 34 catalog checks against a synthetic loopback service, including real TLS handshakes with a private test CA, Music REST/History/Queue mock response contracts, five read-only authorized API response contracts, classified HTTP errors, bounded retries of fixture 503s, and native publication to a local API. Ynison and paid probes are explicitly disabled without network traffic. The synthetic OAuth value is not a credential. These are not complete real SDK implementations: the mock does not prove OAuth/IAM exchange, actual API models, full request parameters, regional behavior, or production equivalence. Existing Python and JS Wire production clients are unchanged.

Scheduler/storage test is local SQLite, not remote D1: a transaction fences stale leases; a 30-minute history epoch gives stable ETag, atomic status/history, bounded delta retention, full fallback, rolling cleanup, and maintenance without changing the last observed status timestamp. Delta representation has its own ETag. Current model replaces changed series rather than appending minimal point diffs. Read-time maintenance can be expensive; production candidate should schedule it independently. Timestamp shape in the internal model is integer seconds, static fallback converts to ISO; compatibility with the live API requires an explicit adapter.

E2E: scheduler acquisition -> native process -> mock HTTP and TLS -> native POST -> SQLite commit -> HTTP status and conditional history -> actual Chrome dashboard via local static-fallback routes. Five cycles per native candidate; not a real Yandex/Cloudflare timing measurement. Browser timing includes a separate cold Chrome launch after publication; do not sum it with earlier stage metrics as simultaneous measurements. 31 virtual days exercise retention and fencing; not a wall-clock soak.

No external calls or production credentials. No Cloudflare resources created. Run on Linux: go build -o core-go core.go; cargo build --release; python test_store.py; python e2e.py. Workflow saves results to logs/artifact. No production deployment.
