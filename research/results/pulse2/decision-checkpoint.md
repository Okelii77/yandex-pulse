## Architecture decision (provisional, not a language winner)
Keep working Python REST SDK and authorized adapters; investigate MarshalX ClientAsync, yamuse and go-yamusic against real sanitized contract fixtures. Neither Go nor Rust is a validated replacement yet. Use native candidate for public monitoring only after differential production-schema tests. Keep JS Wire and actual existing Ynison gate; never enable automatic Ynison with a mock-based result. Keep TypeScript/JS Worker control plane until workerd and real quota-safe benchmarks demonstrate a benefit for WASM; JS and compiled TS are the same runtime. Cloudflare Cron can dispatch a fixed workflow with repository-scoped Actions:write GitHub App/fine-grained credential, OIDC on ingest, slot leases, explicit last_successful_observation and separate last_dispatch. GitHub Scheduler fallback must use same lease. API response accepted is not runner started or result published. New dispatch workflow needs default-branch presence before real test; no change allowed yet.

## Quota model
D1 Free 5M reads/day and 100K writes/day (account shared; verify plan). 34*48*30=48,960 theoretical samples, 34*48=1,632 raw rows/day. Full recomputation 48x/day scans ~2,350,080 rows/day before other operations. Materialization wins versus >48 *cold cache misses* per day, not automatically versus every user request; existing revision cache may make demand-driven snapshots better at low traffic. Prefer lazy one-per-revision materialization with singleflight/atomic publication and retention maintenance, track actual meta.rows_read/written and CPU. For 1000 cold history misses/day full scan ~48.96M, materialized ~2.351M plus additional operations. Indexes and snapshot/delta writes excluded; estimates are not measured Cloudflare costs.
