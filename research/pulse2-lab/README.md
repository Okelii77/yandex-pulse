# Pulse 2.0 reproducibility lab (offline, not production)

All clients use 25 independent requests, explicit batches of 8; the previous 27-request baseline stays in the stage-2 report and is not directly comparable. Same Go loopback HTTP/1.1 fixture, 1s timeouts, no redirects/retry, JSON parsed and payload length verified. Close vs pooling is explicit; urllib is only in close cohort. TLS uses generated trusted CA and IP SAN, no certificate verification bypass. IP avoids DNS rather than benchmarking DNS. Aiohttp, Node, Rust and Go reuse clients for long-lived scenarios. Lazy vs pre-initialized urllib separates SSL/opener startup. Rust currently creates scoped threads per batch; Go spawns goroutines, aiohttp and Node are async. This is a comparison of implementations, not intrinsic language rankings. Fault cases validate 503, 429, deadline and malformed JSON with deterministic variation. No real Yandex calls. Linux /proc/self/status VmHWM and VmRSS after workload, compared to wait4.ru_maxrss; wait4 CPU includes full process launch, warm CPU reported per cycle (not independent CPU measurements); fresh process wall includes launch. 100 cold iterations at 30ms on each of two runners, 100 warm cycles in one process per runner at 80ms; other scenarios 10 exploratory cycles, p99 there is maximum not strong tail evidence. Two runners provide independent replicates; keep raw results separate. No network traffic beyond dependencies and localhost. No use of secrets. Tests are read-only against production because they never contact it.

Known local reproduction: parent allocation 0/64/128 MiB yielded child ru_maxrss 95108/160644/291716 KiB but child VmHWM 644/644/640 KiB. Python local same-process mock test: concurrent lazy opener median CPU 89.90ms vs initialized 29.31ms; 8 SSL contexts alone 61.29ms. This supports (does not prove) SSL context construction as a cause of high CI CPU; compare new paired results. Original run 46138272071 summary preserved in stage2 report.

Build: python -m pip install aiohttp==3.13.3; bash build.sh; python run.py --runner local. For local systems without Rust: bash build.sh --no-rust; python run.py --no-rust --quick. No deployment.

CI writes evidence only to research branch, unique run/attempt paths. No force push, no production credentials. If branch moves during publish, checkout latest and preserve unrelated commits; reject any unexpected branch. Artifact remains if push fails. Public standard runners only.
